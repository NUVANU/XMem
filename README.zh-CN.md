# XMem

**接续项目，而不只是接上一段聊天。**

带来源、适用条件和修订记录的本地工程记忆，支持显式保存与检索。

[English](README.md) · **简体中文**

[快速开始](#快速开始) · [工程记忆 API](src/engineering-memory.ts) · [MCP 契约](src/engineering-mcp-contract.ts) · [X Suite](https://github.com/NUVANU/X-Suite)

持续开发很难只用一个对话完成。换会话或交接 Agent 后，真正难找回的往往是项目里的理由：哪条规则仍有效、接口为什么改过、哪种修复已经失败。

**XMem 将这些历史保存为可以核对的项目知识。**检索相关记录，沿来源回查，确认修订版本与适用条件，再决定是否用于下一项任务。

## 哪些内容值得记住？

| 工程知识 | 为什么保存？ |
| --- | --- |
| 约束与决策 | 保留规则背后的原因，而不只是最新表述 |
| 接口与模块约定 | 为后续改动提供必要背景 |
| 失败与修复尝试 | 保存实际现象，区分有依据的结论与假设 |
| 待定问题与未知项 | 交接后仍看得见不确定性 |
| 任务检查点 | 为接续和对账提供明确位置 |

适合持续维护的仓库、较长的 AI 编码任务，以及重复补充背景成本逐渐增加的多 Agent 协作。

## 用一个小例子理解

假设社区工具预约台确认过一条规则：

> “借用人可以在开始时间之前取消自己的预约。”

后续会话应能找到这条规则、它的来源，以及当时适用的任务和版本。规则变更后，旧修订仍可查阅，但不能悄悄充当当前答案。

类似地，过去一次缺陷分析中的“时区转换导致了问题”，应保留它究竟只是推测，还是已有引用支持的发现。

这是 XMem 支持的记录方式示意，不是模型记忆准确率的实测结论。

## 核心能力

### 带着项目和任务上下文检索

工程检索明确使用项目/workspace 身份、任务引用、任务版本和角色上下文，支持按文件、模块、主题或关键词选择。先预览结果，再展开选定的记录正文。

引用携带修订 ID，以及来源、内容和绑定哈希。消费者可以核对依据，不必把一段脱离背景的摘要直接当作当前事实。

### 保留修订，而不是覆盖历史

保存时提供预期上一修订，通过 compare-and-swap 检查识别写入冲突。来源、适用条件与记录正文共同构成工程证据。

失败记录区分观察、分析状态与支持引用。撤回和对账操作，为变化或失效知识保留可追查的路径。

### 控制检索规模，如实表达缺口

查询设有结果和载荷上限。覆盖不全、来源缺失或结果不确定时，需要保留这些信息；短预览不等于已阅读完整依据，实际采用前应展开对应记录。

### 用明确检查点接续

保存已获准的发现，回读核对，为下一会话建立检查点。安装、会话绑定、保存成功，以及后续检索分别发生，可以分别验证。

## 快速开始

当前公开源码：**V0.1 社区版系列 · 包版本 `0.1.1` · MPL-2.0**，文档所述联合安装配套 **XDev `0.1.2`**。

**要配置可用的 Codex 项目，请按 [X Suite Windows 安装指南](https://github.com/NUVANU/X-Suite/blob/main/INSTALL.md) 操作。**仅构建运行目录，不代表完成项目初始化、取得同意或启用记忆权限。

当前源码构建路径使用 Windows x64、**Node.js 24.20.0** 和 **npm 11.19.0**。在干净 XMem 源码目录执行：

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run check
npm.cmd run build
node tools/stage-runtime.mjs C:\XSuite\xmem-runtime
Set-Location C:\XSuite\xmem-runtime
npm.cmd ci --omit=dev --ignore-scripts
```

目标必须是与源码分开的**全新绝对路径目录**，生成后需保留。当前包包含固定的 Windows x64 SQLite 原生依赖；其他平台需要分别验证依赖与运行时。

工程 MCP 进程入口，在运行目录中执行：

```text
node dist/src/engineering-companion.js
```

按指南完成注册、项目/存储初始化、来源登记和 XDev 协作配置。新项目没有历史记录时，空结果可以是正常情况。

配置好后，可以向编码 Agent 提出：

```text
修改预约模块前，请检索相关项目记忆。
展开准备采用的记录，核对来源与适用条件。
区分历史规则、尚未解决的发现和当前决定。
获准的新发现请保存后回读，并为交接建立检查点。
```

## 技术设计

| 机制 | 提供的能力 |
| --- | --- |
| SQLite 本地存储 | 持久记录、修订及事务操作 |
| 结构化工程记录 | 约束、决策、接口、失败、未知项与笔记 |
| 明确的文件/模块/主题关联 | 选择相关上下文，避免一次加载全部历史 |
| 预览 → 展开 | 先核对引用，再取得选定的证据正文 |
| 修订与内容哈希 | 识别旧引用及内容/绑定变化 |
| 预期上一修订 | 拒绝冲突更新，避免静默覆盖 |
| 类型化 SDK + 结构化 MCP 适配 | 通过同一记忆核心进行集成 |
| 项目存储策略 | 身份保留在 `.xmem`，支持项目内或明确选择的自定义本地存储 |

源码入口：[工程记忆](src/engineering-memory.ts)、[MCP Schema](src/engineering-mcp-contract.ts)、[MCP 适配](src/engineering-mcp.ts)、[存储策略](src/storage-location.ts) 和 [公开包导出](package.json)。

XDev 集成还会核对部署的 XMem 程序与清单。**运行程序完整性检查**与**记忆记录的修订/来源哈希**是不同层次；包版本或内容哈希都不能证明记忆结论本身正确。

## XMem 与编码宿主的关系

XMem 提供持久证据与检索，宿主决定何时调用、怎样把结果提交给模型，以及怎样执行开发。XDev 可以对这个过程施加治理规则。

这是显式工程记忆，与宿主原生 memory 分别存在。不承诺每次上下文压缩后自动注入、完整采集所有对话，或让所有模型都正确采用。历史里保存过的指令，不是当前执行任务的新授权。

绑定和角色用于约束操作范围，不代表已经对真人/Agent 身份做密码学认证，也不充当操作系统隔离。

## 隐私、升级与当前范围

项目配置位于 `.xmem`；数据库与产物可以保留在项目内，也可以使用明确选择的本地目录。已有持久记忆后改变存储位置，需要单独迁移，不能静默切换。

当前文档覆盖有边界的本地 Windows/Codex 保存、回读与新会话检索。其他宿主、系统、无人值守恢复路径及更新的本地构建，需要分别验证。本 README 不声明已测得某个记忆准确率或 Token 节省比例。

记忆在本地保存，检索内容仍可能提交给宿主使用的模型服务商。只保存有权使用的来源，不要向公开仓库或 Issue 上传凭证、私人对话或记忆数据库。

联合部署升级时，新建运行目录并遵循配套部署/清单流程。不要覆盖运行中的数据库，也不要假设新包会自动迁移旧记录。
